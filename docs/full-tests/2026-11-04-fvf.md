## Measured behavior and limits

Final nominal conditions: NN, 27 °C, input common mode 1.1 V, 50 µA reference,
1 pF load, input step 1.05–1.15 V.

| Metric | Schematic | Extracted RC |
| --- | --- | --- |
| DC output at 1.1 V input | 0.458176 V | 0.457701 V |
| Low-frequency gain | 0.80360 V/V | 0.80361 V/V |
| Descending −3 dB bandwidth | 611.4 MHz | 551.0 MHz |
| Output resistance at 1 Hz | 34.90 Ω | 35.22 Ω |
| 1% settling, rise/fall | 6.6 / 7.1 ns | 7.2 / 7.7 ns |
| Nominal local-loop phase margin | 28.65° | 29.29° |

The extracted response has approximately 16% rising overshoot and 31% falling
undershoot, with about 6.2 dB frequency peaking. This is a working, characterized
prototype with a clear damping limitation. Clean DRC/LVS does not resolve that
electrical-quality issue.

The agent checked NN/27 °C, SS/125 °C and FF/−40 °C before and after extraction.
At 10 mV DC samples over 1.05–1.15 V, all four devices remained in model region 2;
the smallest extracted saturation margin was about 26 mV. The initial 0.9 V
input failed the slow/hot headroom check and is retained under `runs/vin090/`.
The final input range is a characterized restriction, not a claim of rail-to-rail
operation. No numerical gain/settling specification was invented as a user requirement.

Scope limits: these are three process/temperature points at fixed supply, not a
full PVT or mismatch qualification. Density/antenna decks were not run. The RC
technology lacks resistor temperature coefficients; resistance-temperature
variation was not established. Native STB did not find an extracted gain-margin
crossing within the sweep, recorded as null rather than infinite gain margin.

## Friction observed

| Friction | What happened and recovery | Maintained capability worth adding |
| --- | --- | --- |
| Environment setup and shell flags | Parent preparation with `set -u` failed on an unset site variable. The agent independently hit `set -e` aborting during site setup, then isolated setup and restored error handling. | A shared site-environment runner for licensed tools, with setup status/logs and flag handling. |
| License-query ambiguity | Newer lmutil returned feature-query errors; IC618's utility obtained usage counts. Even individual Assura feature queries looked unsupported although real Assura DRC/LVS succeeded. | Capability checks based on compatible utilities and actual supported tool execution; do not equate a feature-query failure with tool unavailability. |
| Direct Spectre sandbox execution | The ordinary sandbox produced `SPECTRE-209`. The same deck succeeded when the agent requested reviewed execution. | A specific reviewed Spectre invocation, preserving per-command review and first-failure evidence. |
| Interpreter and SKILL mechanics | Bare `python` was missing; database-property type assumptions failed; an extra parenthesis broke a layout loop. | Verified inventory/PCell recipes and lightweight job preflight, instead of recreating plumbing for each design. |
| Schematic pin geometry | NMOS-style pin escape directions were applied to PMOS. Wire-label calls then received invalid glue. Corrected directions and retries produced a clean schematic. Two incomplete jobs were caught by missing completion markers despite native exit 0. | Pin-aware wire/label creation with preconditions and post-check assertions. Retain completion markers. |
| Model fidelity | Initial hand-written exploration omitted junction areas/perimeters; vendor wrapper defaults distorted capacitance and bandwidth. The agent detected this and switched to generated CDF geometry before claiming final performance. | A reliable saved-schematic netlisting path and explicit exploratory/final provenance. |
| Output containment | OCEAN initially used `~/simulation/buffer` despite `resultsDir`. The agent moved the generated tree into the private project and fixed `asimenv.startup/projectDir` before simulator selection. The parent found no moved files older than the test. Some document/cache probes also used generic `/tmp/fvf_*` paths. | Contained netlisting, temporary/cache paths and output manifests. Protect against collisions with existing runs. |
| Verification engine discovery | Diva DRC stopped at a license-existence check. Assura succeeded. Legacy Assura RCX was retired; Quantus provided working extraction. | Versioned, verified Assura/Quantus run recipes and native-result parsing. |
| Layout text semantics | First LVS matched devices/nets but had a pin error because internal X was labeled like an external port. The agent removed only that label and reran DRC/LVS to a clean match. | Separate physical port labels from internal schematic net naming. |
| Quantus directory conventions | First attempt rejected a different output/LVS directory (`EXTQRCXOPT-244`); the next rejected an absolute temporary path (`LBRCXM-505`). Matching the run directory and using a basename-only temp directory succeeded. | A validated extraction wrapper and explicit output collection. |
| Measurement format and interchange | Initial PSF operating-point parsing returned no records. Raw PEX had different port order, canonical model names, extra CDF fields and `#` nodes. The agent fixed parsing and made an audited translation preserving components. | Reusable PSF readers, explicit interface mapping and tested PEX adapters. |
| Analog validity and quality | Initial slow/hot bias lost headroom; moving the operating point recovered the checked range. Low gain/DC offset and ringing remain disclosed. | Operating-point/corner gates and explicit design acceptance criteria, beyond clean execution or physical reports. |

Most useful next implementation work: promote the successful contained netlisting,
Spectre, Assura, Quantus and PEX-adaptation procedures into reviewed, tested Cadex
helpers. Keep engineering decisions in skills. This single run demonstrates the
end-to-end capability; it does not establish reliability across arbitrary designs.
